# CardSpace 极简交互改造方案

状态：V0.3 已按本方案实施，以下保留设计依据。具体交付及验证边界见末尾。日期：2026-10-22。

## 1. 产品原则

交互顺序统一为「用户提供内容 → 系统保存并理解 → 呈现可用结果 → 用户按需修正」。减少用户提交前必须作出的分类与填写决定。

- 录入只要求内容。来源、格式、标题、摘要、类型与标签由规则或已授权的模型处理。
- 原始输入先持久化，AI 失败不影响保存。
- 默认结果可直接使用；每个自动字段都能在结果上直接修改。
- 人工改过的字段由用户接管，后续自动任务尊重接管状态。
- 可逆操作直接完成并提供撤销；改变事实、观点、证据结论与破坏性操作保持明确的人类决策。
- 不使用模型自报的置信度数值作为自动应用的唯一依据。不确定时先保留原文与保守结果。
- 全部基础功能在没有模型配置时可用。外发与预算范围经用户设置后，范围内的自动处理不逐次询问。

## 2. 首页与必要按钮

默认首页保留搜索框、一个「记一下」入口与内容卡片。点击「记一下」后只呈现一个输入区域与「保存」。输入区域支持文字、链接、粘贴 JSON、拖入文件，附件图标为不能拖放时提供可发现的文件入口。搜索与录入分别承担清楚的用途，不自动把普通搜索词保存成笔记。

收藏、复制、归档等操作进入卡片的「更多」菜单；常用动作在键盘聚焦时可发现，手机上可点击。筛选、排序和展示方式合并到「视图」菜单。现有常用导航保留，减少首页同时展开的选项，不在本轮强行重做整个信息架构。

常驻控件：搜索、记一下；录入过程中显示保存/关闭/附件；内容详情提供可发现的修改与更多入口。高风险建议按需显示采用/保留原版；恢复数据库保留确认。

## 3. 录入改造

替换 Capture 中的模式切换、来源选择、标题输入、类型选择、标签输入与强制预览。统一提交到 CaptureService。

识别顺序：有效文件与内容结构 → 已支持的公开分享 URL → 受支持的 JSON Schema → 明确角色文本 → 普通笔记。多个链接、URL 加正文等混合输入先完整保存；规则不能可靠拆分时保留为笔记，不静默丢掉剩余文字。

- ChatGPT / DeepSeek 分享链接：自动选择现有来源适配器，规范化身份并去重，采集快照、构建问题引用和卡片。
- JSON：按内容验证对话结构，不能仅看扩展名。结构不支持时明确保留状态，不虚构角色。
- 角色文本：明确标记时自动解析；只有局部歧义时，结果上提示「检查对话结构」，只编辑相关片段。
- 普通文本：立即保存成笔记，自动给出可编辑标题与摘要。
- PDF / DOCX / MD / TXT：默认进入参考资料，按内容识别可确定的对话例外；以「已存入参考资料」反馈去向，保留转为笔记等后续入口。
- 不支持的链接：保存链接备忘并明确未采集正文。私有地址与受限页面不绕过登录。

取消强制「预览并确认 → 确认导入」两步。常规内容只需一次保存；文件拖入先显示暂存预览，用户仍用同一个保存动作提交，避免误拖即入库。

反馈区分「原始输入已保存」「正在读取对话」「已完成」「部分内容未取得」「需补充来源」。链接文本保存成功不等于对话已取得。失败后的结果就地提供重试或粘贴原文，不要求用户前往任务中心排障。

## 4. 自动填充与人工修改

| 字段 | 规则默认值 | 可选 AI 增强 | 人工修改 |
|---|---|---|---|
| 来源平台 | 官方域名、结构标记 | 不由模型猜造平台 | 更多 → 修正来源 |
| 标题 | 来源标题、首个完整问题、首个有效句 | 提供忠实的简短标题 | 点击标题直接修改 |
| 摘要 | 提取式预览、保留原文位置 | 生成有原文引用的摘要 | 点击摘要直接修改 |
| 内容类型 | 对话结构或文件属性；其余默认笔记 | 可给出知识/项目等候选 | 更多 → 更改类型 |
| 标签 | 匹配已有主题、先少量复用 | 在现有主题中补充，避免无限新建 | 点击标签增删 |
| 时间、消息顺序 | 采用可验证元数据 | 不猜测 | 仅在来源信息中校正 |
| 相关内容 | 现有标签和文本相似度 | 可补充候选关联 | 查看、保留、取消 |
| 事实与证据状态 | 保留当前状态 | 提交有依据的建议 | 人类决定，不能因模型生成就标为有支持证据 |

建议首版把新卡片的标题、摘要和候选标签作为低风险、可撤销的自动展示字段；正文保留原始表达。表达整理先提供衍生版本；涉及新事实、观点或结论变更时才进入显式审批。

就地编辑使用可发现的编辑图标、键盘焦点与触屏入口。正文进入聚焦编辑器，失焦/防抖保存到新版本，显示保存状态与撤销；输入法组合期间不提交，关闭或离开时处理未保存状态。保留草稿与版本冲突提示。

每个字段维护生成来源、所依据的快照/修订、生成策略/模型版本、人工接管状态。用户改标题后，只锁定标题，不妨碍其他未修改字段继续更新。显式「重新生成此项」才解除或替换用户指定字段；删除自动标签需要记录否决，不在下一轮重新加回。

## 5. 阅读、检索与知识维护

卡片默认只展示标题、短摘要与必要来源。详情可自动形成有原文引用的摘要/要点展示层；它与原文分别保存，人工修订后的展示优先于自动生成版本。标签、消息数量、完整时间在有用的场景或详情中展示，取消无意义的「缺少标签」「内容太短」提醒。

详情以当前内容为主。原文与来源、历史版本、关联引用收进可展开区。用户搜索命中历史问题时自动定位对应原文；DeepSeek 思考片段继续默认折叠。保留当前编辑版本与不可变原始快照的清楚关系。

检索先即时返回本地结果。已配置且在用户授权范围内时自动补充语义召回，取消每次搜索的「语义增强」判断。加入防抖、缓存和取消过时任务；用户已开始操作的结果不因异步重排突然移动。没有匹配记录时明确返回空结果。

重复检测、索引更新、轻量主题和候选关联维护由后台执行。精确重复自动复用；疑似相似只显示相关候选，不自动合并。自动维护合并为低频摘要，不让每个规则命中成为待办。只把需要用户改变内容或作出选择的事项汇总到一个待确认入口。

参考资料上传后自动解析、分块和索引。系统可为当前卡片预选相关段落与引用目标，用户从卡片发起时无需再次选择同一张卡片。自动发现的匹配是候选参考，不能自动声称支持某个结论。

归档改为直接完成并提供撤销，不再弹确认窗口。恢复数据库、永久删除或批量合并等操作继续明确确认；本版本没有永久删除按钮，不因本方案自动新增。

## 6. 规则、AI 与人类决策分工

规则：URL/平台识别、文件识别、消息 ID/角色/顺序、哈希去重、原始保存、回退标题、版本冲突、任务与索引。

AI（可选、已授权）：标题润色、摘要、有限主题建议、语义归组与候选关联。生成结果做结构校验、原文引用校验，不执行资料中的指令。

人类：提供内容、纠正自动结果、API 密钥与外发授权、事实/观点变更、确认高风险数据操作。

用户偏好记录为可查看的明确规则，例如「当前工作区新记录默认存入某主题」。不因一次修改就全局推断偏好；涉及跨记录行为时可询问一次是否沿用。

## 7. 对现有工程的改动

- 前端：Capture 替换为单一 CaptureComposer；列表工具条收拢；CardDrawer 加入就地编辑、折叠上下文与统一撤销；任务失败在内容就地处理。
- API：新增统一 capture 接口，接收原始文本/上传文件与可选上下文。前端不再被要求提供 kind、provider、title、tags。保留现有 notes/imports 接口兼容 MCP 与社区调用。
- 服务：新增 CaptureService 与确定性路由，调用现有来源、卡片和参考资料服务；新增分字段 EnrichmentService，后台填充元信息。
- 持久化：新增 captures，独立记录原始提交、采集状态、结果对象与任务。扩展字段来源/人工接管、自动建议及忽略状态；用新迁移升级旧数据。
- 权限：后端区分新增元信息、修改人工字段、改写正文、证据判定等操作，不为减少审批而开放通用 Agent PATCH。客户端声明低风险不能绕过服务规则。
- 并发：人工编辑携带期望版本号。AI 完成后逐字段校验基础版本与人工锁；冲突时只保留候选，防止晚到的任务覆盖用户输入。
- 迁移：已有卡片正文与元信息按人工/受保护内容保守处理，不为补齐标签或摘要自动重写全库。
- 模型设置：提供服务预设，预填可确定的地址；密钥由用户输入。可用时发现模型列表，失败时保留手动配置。自动整理范围和预算明确一次设置，默认离线规则可用。

## 8. 实施顺序与验收

第一阶段：统一录入、规则识别、先保存、取消常规强制预览、就地反馈。没有模型也完成极简闭环。

第二阶段：字段生成来源、人工接管、就地编辑、撤销与并发保护，再接自动 AI 元信息生成。先有用户控制，再扩大自动写入。

第三阶段：自动语义补充、资料候选匹配、静默维护、合并必要审批与偏好规则。

验收目标是待测试的产品目标，不是已达到的数据：

- 新记录无需填写标题、类型、标签；常规输入从提交到可查看结果不要求额外决定。
- 受支持公开链接无需选择平台；文本/JSON/文件不要求先选模式。
- 原始输入提交成功即持久化；解析和 AI 失败后仍可读取、重试。
- 自动标题、摘要和标签均能直接修改，用户删除的建议不反复出现。
- 用户修改后，重导入、索引重建和迟到 AI 任务均不能覆盖受保护字段。
- 常规归档无确认弹窗且可恢复；高风险操作仍要求明确决策。
- 没有模型或网络时能保存、浏览、编辑和关键词搜索，不能用无内容的占位卡假装导入完成。
- 在明确授权范围外没有模型调用，自动维护具有预算、去重与静默条件。
- 使用合成场景验证点击/决定次数，并邀请真实用户完成「存入、找回、纠正」任务，评估纠正率、耗时和不必要打断。


## 9. V0.3 交付说明

已实施统一文字/链接/JSON/附件入口、原始输入先保存、规则标题摘要主题、独立授权的可选 AI 元信息、逐字段接管与否决主题、就地编辑与本机草稿、自动保存和撤销、视图菜单、折叠原文/历史/关联、语义补充及失败回退、当前卡片候选引用、资料另存笔记、安静的规则体检、MIT 源码分发与旧数据保护迁移。

实现采用保守范围：普通文字不猜测知识/项目类型；必要时在「更多」修正类型。来源修正只更改显示名称，真实适配器与原文不被篡改。AI 摘要首版限制为原文连续片段；不凭空生成事实。自动模型配额是每日请求次数与输入字数，不是消费金额保证；预算不足或输出不合法时保留本地结果。疑似相关内容按需计算，不自动合并或认定支持证据。未支持的对话 JSON 文件保留原始输入并提示补充，不显示强制角色编辑大表单。

新录入默认主题为明确可查看的设置，不从一次人工编辑推断全局偏好。文件暂存不跨浏览器刷新持久化，提交后的完整附件才存入 SQLite。正文编辑草稿暂存在当前浏览器，冲突保留草稿并由用户选择重试。旧数据迁移和真实 v1 备份恢复已用自动化验证；真实模型内容质量及多设备用户研究未完成，不将这些长期指标列为本轮已验收。
