## 浏览器人工端到端

通过真实内嵌浏览器验证以下链路：

1. 打开空工作台，进入快速记录，输入 Markdown、标签并保存。
2. 详情展示 Markdown 原文，收藏后数量更新。
3. 本地整理生成候选修订，在知识体检页打开对比并采用，当前版本更新。
4. 粘贴四条问答，预览确认用户 / 助手角色，提交持久化导入任务。
5. 搜索「流量」找到原始提问，打开结果直接进入原始资料，命中消息高亮并保留完整回答。

浏览器验证发现并修复：后台任务完成后查询缓存未自动刷新。现在全局观察持久化任务状态，并刷新相关卡片 / 问题 / 审批数据。

截图位于 `output/playwright/`（临时验收产物，不提交版本控制）。浏览器以约 660px 宽布局验证移动导航、双列卡片和抽屉；未进行多设备真机兼容性矩阵测试。

## 规模试验

运行 `.venv/bin/python scripts/benchmark.py`。使用独立临时 SQLite，生成 10,000 张短中文卡片（每张约 200 字），执行 5 种查询各 5 次，共 25 次。

本机观测：数据生成约 1.42 秒，搜索 P50 约 121.78ms，P95 约 239.80ms，最大约 283.00ms。该结果仅针对本机此合成负载，不代表长对话、含附件数据、不同硬件或完整真实知识库均满足同样指标。

规模试验期间将 FTS 删除 / 更新改为与 cards 的 SQLite rowid 对齐，避免每次编辑按未索引的文本 ID 扫描整个虚表；初次启动会为现有数据重建索引映射。

## 2026-10-23 连接恢复与操作入口修复

- 复现原页「重新连接」后依然 401：前端把握手结果永久缓存，重试只重新读数据，没有重建会话。同主机不同端口服务原来共享 Cookie 名称，也可能覆盖彼此凭据。
- 前端检查握手响应，401 最多续期/重发一次，并发请求共享续期；握手失败不缓存为成功，取消和 403 不重复提交。手动重新连接会重建会话并刷新查询，错误提示不再要求界面用户配置 Agent token。
- 后端按端口隔离 Cookie 名称，保持 HttpOnly / SameSite=strict 与 Origin / Host 防护。没有增加匿名访问能力。
- 搜索框右侧改为「搜索」提交；「＋ 新建记忆」移至页面标题旁，窄屏保持醒目。录入弹窗标题对应为「新建记忆」。
- `npm test` 通过 64 项后端 + 10 项前端行为测试；新增覆盖过期续期、并发、失败握手、重试上限、写入请求保留、权限拒绝、取消、多端口 Cookie 隔离，以及搜索/新建行为分离。
- 生产构建通过。在与用户相同的 662×737 内嵌浏览器中验证主页和设置页可读取、搜索不打开录入、新建独立打开弹窗。正式数据记录数量更新前后相同，未保存合成记录。
